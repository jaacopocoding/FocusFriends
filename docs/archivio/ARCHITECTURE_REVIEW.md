# FocusFriends: Architecture review

Reviewed snapshot: branch `main`, commit `2043b39`. Input: `ARCHITECTURE.md` plus read-only inspection of the source files named in each finding. Nothing was run, built or modified.

## 1. Verdict

**NEEDS REVISION**

The design is sound for a single-user, offline desktop app: no network surface, atomic file writes, versioned data with backups, and a tested Foundation-only core. It needs targeted changes rather than a redesign: the timer records full focus time after the Mac has slept (F-01), and the persistence layer fails silently on every error path (F-03, F-04). Nothing found is exploitable or loses data in normal use, so no finding is Critical.

## 4. What is built well

- **Testable domain core.** `SessionLog`, `Profile`, `CustomTimers`, `BreakCycle`, `CompanionRewards`, `AmbientSound` and `MusicLibrary` are Foundation-only. `SessionLog.init(directory:now:timeZone:)` injects directory, clock and time zone, and 23 test sections cover migration, recovery, time zones, backups and unlock rules. This is what makes the persistence layer trustworthy.
- **Data-safety design.** Writes are atomic. The file format is versioned, an intact copy of the previous format is kept on migration, and a newer-version file is never rewritten. An undecodable file is moved aside instead of deleted. One backup per day is kept for 7 days. A 30-second heartbeat file lets a crashed focus be recovered with pause time subtracted. The weaknesses in F-03 and F-04 are about reporting and tolerance, not about the underlying approach.
- **No attack surface to speak of.** A search of `Sources/` finds no `URLSession`, `http(s)://`, `Process(`, `NSTask`, `NSAppleScript` or web view. Free-text input is trimmed, stripped of control characters and length-capped (`Subject.clean`, `SessionNote.clean`, `FocusNotes.clean`, `Profile.clean`). The CSV export guards formula injection for `= + - @`, tab and carriage return.
- **Stable statistics across time zones and DST.** The wall-clock `localStart` string keeps a session on the day it was studied, and the tests cover it.
- **Clear UI contract.** The card receives an immutable `MenuCardState` and a `MenuCardActions` closure struct, so the view layer does not touch models directly.
- **Audio hygiene.** The render path avoids allocation, and the engine is paused after the fade-out so an idle app uses no audio CPU.
- **Single-threaded model.** All logic runs on the main thread with one render callback, which removes most concurrency hazards (F-12 is the one exception).

## 5. Prioritized action list

1. **Handle sleep and wake in the timer** so slept time is not recorded as study time (F-01).
2. **Make loading tolerant and visible**: element-wise decode, distinguish absent from unreadable, tell the user when data was set aside (F-04).
3. **Surface persistence failures** instead of swallowing them, and stop notifying observers on failed saves (F-03).
4. **Stop recomputing full statistics every second** while the card is open (F-02).
5. **Move music-folder scanning off the main thread** and cache the result (F-05).
6. **Extract the timer rules and reward evaluation out of the UI classes**, then **add tests and CI** for them (F-06, F-07).
7. **Fix the rating overwrite** in the reflection card (F-08).
8. **Show the read-only state** and delete `in-corso.json` only after a successful add (F-09).
9. **Report failures of export, phrases file and audio start** (F-13).
10. **Trim background work**: dirty-flag the dashboard and garden reloads, group sessions by day once (F-11), and stop the idle 30 Hz walker timer (F-10).
11. **Replace the unsynchronised synth parameters** with atomics (F-12).
12. **Improve distribution hygiene**: checksums, fail the build on signing failure, consider notarisation (F-14).
13. **Correct the documentation and centralise paths and keys** (F-15, F-16).
